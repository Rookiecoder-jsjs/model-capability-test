## 关键扣分依据

### 1. 实际绘制几何与“落位探针”不是同一件事

[objects.ts](../../project/src/scene/objects.ts) 第 20–24 行的 `sub()` 将子零件平移写入矩阵 `[3, 7, 11]`，而 [render2d.ts](../../project/src/engine/render2d.ts) 的 `box()` 读取 `[12, 13, 14]`。

本次在实际浏览器中临时观察 `renderer.box()` 参数，并随即恢复方法：尺寸同为 `1.58 × 0.04 × 2.30` 的服务器底板、顶板，实际渲染平移均为约 `(1.41548, 0.82915, 0.73902)`。两块本应分离的板重合在服务器原点。改变的是未被渲染器读取的分量。

这不是概念造型与工业精度的差别，而是装配面、支撑位置与外壳边界的基础错误。原验证只证明节点原点抵达预设坐标，不能证明实际绘制面正确，因此 C2 为 0，而非因缺少实测而记零。

证据：[真实渲染参数](evidence/geometry.json)、[服务器截图](evidence/1366-server.png)、[原验证脚本](../../project/tools/verify.mjs)。

### 2. 身份持续，但最终完整结构没有持续进入窗口

实际引用比较支持芯片、板卡、服务器、原机柜和集群一直是同一批对象；这部分应给分。

但 [stage.ts](../../project/src/app/stage.ts) 第 151 行起仅在 `embed < 0.5` 时绘制机柜和硬件链。窗口中保留的是三个软件平台，原集群被停止绘制，不能称作完整四层结构进入应用。

此外，正反向固定进度探查中，`p=0.10` 的世界矩阵最大分量差约为 `0.04434`，`p=0.32` 约为 `0.01209`。这是同步采样所暴露的到达顺序依赖，不是前台掉帧指标，也不代表每个停点都会持续跳动。原脚本只在已完全落位的 `p=0.6` 比较，不能外推到“任意进度均一致”。

证据：[引用与矩阵比较](evidence/geometry.json)、[最终窗口](evidence/1366-agent.png)。这些问题影响 C1；平台形成节奏与四层表达另由 C3 评价，没有再追加表外扣分。

### 3. 四层与标签的实际表达不足

在 `p=0.6875`，模型、Harness、Agent 三个平台的升起进度都是约 `0.70681`。三者使用相同 `rise`，没有分别体现各层逐步加入的节奏。

逐章巡检还发现旧标签残留：服务器章仍显示 Agent、Harness、模型层标签；Harness 章残留芯片与服务器等此前标签。`applyLabels()` 只更新本帧返回的标签，没有统一清除本帧不再出现的旧标签。截图中原窗口的结构也超出运行区边界而被裁切。

稳定正文对 body 背景的计算对比度约 **12.46:1**，达到要求，这部分不扣分；该检查不覆盖淡入中间态、模型经过处或所有辅助标签背景。

证据：[服务器章](evidence/1366-server.png)、[Harness 章](evidence/1366-harness.png)、[窗口](evidence/1366-agent.png)、[正文样式与对比度](evidence/text-contrast.json)。截图右侧粉色工具浮钮来自浏览器环境，不计为模型 UI。

### 4. 有文字层级，但缺少逐章适配

八章都有语义断行、700 标题字重、导航和能力项／交付区分，不能按“无设计”打分。

但实际计算样式显示，1366×893 下八章标题均为 **32.784px**，1025×700 下均为 **24.8px**。`buildChapter()` 对所有章节都使用同一 `t-h1`；`layoutChapters()` 根据固定高的章容器而非内容高度决定紧凑模式，容易让所有章节统一缩小。按细则“有统一风格但各章机械共用字号”的锚点给 C4 = 2。

本次加载状态只确认 Inter Variable；中文实际回退到系统字体的具体字形未单独查验，不把声明引入 Noto Sans SC 当作已经使用该字体的证据，也不据此认定中文没有粗体。

证据：[1366 计算样式](evidence/layout-1366.json)、[1025 计算样式](evidence/layout-1025.json)、[首屏](evidence/1366-chip.png)。

### 5. 按钮不是摆设，但与 Harness 动画脱节

本次实际点击了芯片 → Harness → 服务器 → Agent → 显卡导航，位置与当前章对应。实际完成了：运行中停止、停止后重放、运行中再次启动、两次完整运行、点击下载并打开导出文件。下载的 Markdown 标题、进展及三条待办正确；运行时下载禁用，完成后启用。

然而从初始状态到运行、停止、重启、完成，原执行信号 `exec` 始终约为 **0.293436**；画布在运行早期达到 **263** 次提交后直到两轮完成仍未继续更新。说明状态列表与原 Harness 信号没有同步。停止时进度约 28.3%，点击文案为“继续运行”的按钮后回到第一步，而非恢复此前位置。

证据：[交互原始记录](evidence/interactions.json)、[已完成界面](evidence/agent-completed.png)。导出原文件包含固定输入资料，按仓库边界不另存提示词副本，仅记录实际下载文件哈希及内容核对结果。

### 6. 阅读降级存在明确缺项

实际检查了三种桌面尺寸、390×844、小屏静态模式、根字号 32px 模拟的 200% 文字和减少动态模式。八章主要文案视觉上存在，页面没有横向溢出；首个 Tab 焦点为“跳到正文”，轮廓为 2px。

但静态阅读时，七章仍保留 `aria-hidden=true`，虽然肉眼可见，却从无障碍树隐藏。禁用 JavaScript 后只看到标题和两段提示语，没有所承诺的八章基础文案。这属于明确降级缺陷，C8 = 2。

证据：[模式检查](evidence/modes.json)、[无 JS 页面](evidence/no-javascript.png)、[无 JS 快照](evidence/no-javascript.txt)、[390 宽截图](evidence/mobile-390.png)。未使用屏幕阅读器实测，DOM 隐藏结论不能扩写为某款读屏器实测结果。

### 7. 工程可运行，原“全通过”不足以支撑高分

本次按锁文件安装并成功执行生产构建。构建出现 CSS `Unexpected "}"` 警告，对应 [app.css](../../project/src/styles/app.css) 末段未完成的 `html.text-200` 选择器。它没有阻止构建，不能据此触发 G0 失败。

原测试有真实日志，但身份测试主要比较名称，接触测试主要比较节点原点和目标点，遗漏实际渲染错误。因此 C9 评为“有基本交付、验证薄弱”的 2 分；**没有把测试漏检断言成证据造假**。

证据：[安装日志](evidence/install.txt)、[构建日志](evidence/build.txt)、[独立复核脚本](evidence/review.mjs)。首次网络与监听沙箱错误属于评测环境，不计模型失败。
