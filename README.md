# 模型能力测试（Model Capability Test）

本仓库保存模型能力测评的实际结果：原始回答、生成项目或媒体、运行条件、验证证据及评分。提示词、测试输入与评分标准维护在独立仓库，这里通过来源与版本引用关联。

一条结果代表一次运行。同一模型可以对同一道题重复测评；模型版本、参数、工具和人工干预都需要记录，以便判断结果是否可比。文本、代码、视觉、音频等任务共用归档结构，按需保存各自产物。

## 目录结构

```text
mt/
├── AGENTS.md                    # 归档规范与 agent 工作流程
├── README.md
├── results/
│   ├── index.csv                # 每行一次运行，通过 path 定位
│   └── <model>/<prompt_id>/
│       └── runs/<run_id>/        # 新记录使用 schema v2
│           ├── meta.json        # 运行事实与来源
│           ├── output.md        # 原始文本输出或非文本产物清单
│           ├── report.md        # 评测者说明（可选）
│           ├── project/         # 生成项目／脚本（可选）
│           ├── artifacts/       # 生成图片／音频／文档等（可选）
│           ├── evidence/        # 真实验证证据（可选）
│           └── assessments/     # 后续评分、复核与纠错（可选）
└── tools/                       # 通用采录与校验脚本（按需）
```

已有直接位于 `<model>/<prompt_id>/` 的记录按 v1 保留。新规范不迁移旧结果；同一题的新运行放入 `runs/`，通过索引中的完整路径区分。完整格式见 [AGENTS.md](AGENTS.md)。

## 使用原则

- 一次测评的所有产出都进自己的 `results/` 运行目录，不在根目录另开项目。
- 原始输出与评测者结论分开；已提交产出冻结，评分、复核和作废只追加记录。
- 失败、拒答、超时和缺失信息也属于结果。不编造模型身份、参数或测试数字，不静默修复模型答案。
- 比较前核对题目版本、运行条件和评分量尺，不能只挑最好的一次。
- 本仓库公开，入库前检查凭据、个人信息、素材权限与附件体积。

## 浏览结果

从 [results/index.csv](results/index.csv) 查找记录，按 `path` 打开对应目录。v2 的 `judge_score` 留空，评分与满分、标准和理由一起保存在 `assessments/` 中。

当前保留的 v1 示例是 [space-bunny-free / frontend-001](results/space-bunny-free/frontend-001/output.md)，包含前端项目和已有验证证据。原有验证声明以该记录为准；更新仓库规范不代表重新验证了项目。
